# 네트워크 복구 회귀 검사 (#107)

저장소 루트에서 `bash Tools/NetworkRecovery/run.sh` 실행 (Xcode 26, macOS).
실제 앱의 오류 분류·TourAPI 응답 파싱·Planning/RouteConfirmation/DestinationDetail ViewModel·사진 저장소를 컴파일합니다.
URLProtocol과 길찾기 응답 대역만 사용하므로 외부 요청, API 키, 실제 여행 저장소를 사용하지 않습니다.
앱 타깃이나 SwiftData 스키마는 바꾸지 않습니다.

검사: 정상 빈 응답/통신 오류 구분, 키 인코딩, 재시도와 선택 보존, 경로 중복/취소/이전 응답 덮어쓰기 방지,
사진 중복 다운로드 방지, 재실행 시 오프라인 읽기, 백업 제외, 완료 여행만 삭제, 손상 파일 복구.
탐색→상세 사진 재사용과 1600/2400px 해상도 유지, 이미지 오류별 재시도, 공유 다운로드 취소 격리,
상세 거리·시간 오류 분류 및 실패 항목만 재연결 시 재요청하는 조건도 검사합니다.

## 실기기에서 추가 확인

- 12번에서 사진을 받은 뒤 비행기 모드 → 사진 선택 → 12-(1): 상세 사진/주소/선택 버튼 유지.
- 12-(1)의 거리·시간 조회 실패: `wifi.exclamationmark`와 연결 안내/재시도 표시. 복구 시 거리·시간만 재조회.
- 캐시에 없는 상세 사진의 다운로드 실패: 빈칸 대신 오류/재시도 표시. 복구 시 해당 사진 재요청.
- 성공한 상세 사진/거리·시간은 재연결만으로 초기화하지 않음. 뒤로/빠른 재진입 때 이전 요청이 덮어쓰지 않음.
- 13번 진입 전 비행기 모드: 빈 결과 대신 연결 오류 → 연결 복구 후 추천 자동 표시.
- 13번에서 선택/넘김 → 14번 → 뒤로: 선택을 비우고 추천 목록을 처음부터 다시 표시. 재연결만으로는 기존 선택 유지.
- 14번 경로 로딩 중 연결 차단: 무한 로딩 없이 오류 → 재시도/재연결 시 지도와 경로 회복.
- 14번에서 요청 중 빠르게 뒤로/재진입, 편집/순서 변경: 최신 경로만 표시.
- 여행 계획 확정 후 사진 다운로드를 기다리고 비행기 모드/강제 종료: 15번 저장된 사진 표시.
- 저장하지 못한 사진: 회색 빈칸 대신 오류/재시도, 연결 복구 시 다시 로딩.
- 여행 완료 저장 실패: 캐시 유지. 성공: 해당 여행의 임시 캐시만 삭제.
- 사용자 첨부 사진과 과거 기록은 삭제하지 않음. 완료 후 기록의 원격 사진은 기존대로 네트워크가 필요할 수 있음.

지도 타일은 Naver SDK가 관리하며 이 캐시의 대상이 아닙니다. 연결 복구 시 지도 인스턴스를 갱신합니다.
네트워크 경로 감지는 인터넷/업체 서버의 실제 정상 응답을 보장하지 않으므로 요청 오류와 수동 재시도를 유지합니다.
탐색 사진은 압축 데이터만 메모리 캐시(24MB 비용 제한, 최대 14개)에 보관합니다. 앱 종료/메모리 압박/캐시 축출 후에는
다시 다운로드해야 하며, 24MB보다 큰 개별 원본은 캐시하지 않습니다. 여행 썸네일의 디스크 캐시와는 별도입니다.
