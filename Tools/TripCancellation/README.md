# 여행 중단 검증 (#129)

## 정책

- 15번 여행 진행 화면의 스크롤 내용 맨 아래에 밑줄 있는 `여행을 중단하시겠어요?` 버튼을 표시합니다. 하단 고정 `여행 마치기`는 기존 동작을 유지합니다.
- 확인창에서 `취소`를 누르면 데이터/화면/자동 복원 상태를 변경하지 않습니다.
- `여행 중단` 확정 시 활성 여행 ID 한 건을 조회해 미완료 여부를 확인하고 삭제합니다.
- 여행의 경로(RouteStop), 기록 사진(TripPhoto)은 기존 cascade 관계로 삭제합니다. 새 모델/스키마/마이그레이션을 추가하지 않습니다.
- 다른 여행의 미저장 편집까지 저장하거나 rollback하지 않도록 별도 ModelContext에서 삭제합니다.
- 저장 성공 후에만 세션·활성/준비 여행 ID를 비우고 홈 스택을 초기화합니다. 빈 활성 ID를 저장해 구버전의 미완료 여행 자동 검색도 다시 실행하지 않습니다.
- 해당 여행의 전용 썸네일 폴더는 기존 TripImageStore.removeTrip으로 정리합니다. 다운로드가 늦게 끝나도 폴더를 다시 만들지 않습니다.
- URL 기준 공용 메모리/네트워크 캐시는 다른 화면과 공유하므로 전체 삭제하지 않습니다. 전용 디스크 캐시 삭제는 기존 저장소 정책에 따라 best-effort입니다.
- 저장 실패 시 활성 여행·복원 ID·캐시를 유지하고 오류를 표시합니다. 중단 취소(되돌리기)/임시 보관 기능은 제공하지 않습니다.
- 방문 확인·여행 기록·픽셀 획득 화면으로 이동하지 않으며 기존 완료 여행과 UserPixel 방문 횟수는 유지합니다.
- 서버 호출 없이 기기 안에서 처리합니다.

## 자동 검사

```sh
bash Tools/TripCancellation/run.sh
bash Tools/NetworkRecovery/run.sh
```

첫 검사는 별도 UserDefaults suite와 메모리/임시 디스크 SwiftData 저장소만 사용합니다. 실제 앱 데이터에는 접근하지 않습니다.
현재 여행과 종속 데이터만 삭제, 다른 여행/픽셀/미저장 편집 보존, 중복·다른 여행·완료 여행 중단 거부, 읽기 전용 저장 실패 후 상태 유지, 저장소를 다시 열어도 복원되지 않음을 확인합니다.
읽기 전용 저장 실패 검증 중 출력되는 `Code=513`은 의도한 오류입니다.
두 번째 검사는 공용 캐시 정리 시 다른 여행의 사진 보존과 진행 중 다운로드의 파일 재생성 방지도 확인합니다.

## 실기기 확인

- 진행 화면에서 여행 중단 → 취소: 같은 여행, 경로와 길안내 버튼 유지.
- 여행 중단 → 확정: 일반 홈으로 이동. 앱 강제 종료 후 다시 실행해도 이전 여행이 나타나지 않음.
- 여행 마치기: 기존 방문 확인 → 기록 → 픽셀 획득 흐름이 그대로 동작.
- 기존 히스토리, 픽셀/방문 횟수, 다른 여행 기록이 바뀌지 않음.
- 오프라인 및 사진 다운로드 중 중단, 큰 글자 크기, VoiceOver로 버튼/확인창 확인.

프리뷰는 버튼 배치·확인창 확인용이며, 실제 중단 후 홈 복귀는 활성 여행이 저장된 앱 흐름에서 확인합니다.
